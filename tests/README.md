# テスト

`smile-watch.html` の回帰テストです。実カメラなしで、覚醒スコアの算出から書き出しまでを通しで確認します。

## 実行

```bash
npm install
npm test
```

Chromium は Playwright が用意します（`npx playwright install chromium`）。

## 構成

| ファイル | 役割 |
|---|---|
| `stub-vision.mjs` | MediaPipe `FaceLandmarker` のスタブ。`window.__scenario` から blendshape を組み立てて返す |
| `harness.mjs` | `smile-watch.html` をテスト用に書き換えて静的サーバーで配る |
| `run.mjs` | Chromium で操作しながら検証する本体 |

## 仕組み

アプリは単一 HTML なので、`harness.mjs` が読み込み時に 4 点だけ書き換えます。

1. MediaPipe の動的 import を `stub-vision.mjs` に差し替える
2. フォントの読み込みを止める（テストを外部に依存させない）
3. 時間の定数を 12 倍速にする
4. 内部状態を覗くフック `window.__test` を足す

置換元の文字列が見つからない場合は例外で止まります。アプリ側を変えたときは `harness.mjs` も追随してください。

### 時間を詰めるときの注意

サンプリング間隔だけを短くしても、計測ループは `requestAnimationFrame`（約 16.7ms）で回るためそれ以上は詰まりません。窓の中のサンプル数が減り、覚醒スコアが出なくなります。

そのため `SAMPLE_MS` と `WINDOW_MS` を同じ倍率で縮め、**1 窓あたり 300 サンプル**という実機と同じ密度を保っています。

### シナリオ

`window.__scenario` に「どんな顔が写っているか」を入れると、スタブがそれに応じた blendshape を返します。眠気は次の 3 つを同時に強めて表現します。

- 開瞼度そのものを下げる
- ゆらぎ幅を大きくする（開き具合を一定に保てなくなる）
- 左右差を大きくする（左右の動きが揃わなくなる）

乱数は使わず、周期の異なる正弦波でゆらぎを作っているので実行ごとに同じ結果になります。

## 検証している範囲

| 節 | 内容 |
|---|---|
| 1 | 覚醒指標。覚醒時 90 以上、眠気時 45 未満、PERCLOS / ゆらぎ / 左右差 が上昇すること |
| 2 | 励ましの優先順位（眠気 > 笑顔）とクールダウン |
| 3 | 不在判定と復帰 |
| 4 | 再キャリブレーション。スコアが戻ること、継続計測がリセットされること |
| 5 | 保存。まとめ書き、再読み込み後も残ること、セッション番号の継続、保存期間を過ぎた記録の破棄 |
| 6 | CSV（BOM / CRLF / 見出し / 列数 / 時刻書式）と JSON（キー / 設定 / 基準 / イベント / 範囲指定） |
| 7 | 記録の消去とセッション境界。全セッションに開始イベントが対応すること |
| 8 | 停止と再開でセッション番号が分かれること |
| 9 | 覚醒メッセージの文面 |
| 10 | 同梱アセットがあればそちらを選ぶこと |
| 11 | JavaScript エラーが出ていないこと |

### 時間に依存する検証で気をつけたこと

計測ループは動き続けているので、素朴に書くと「何を確かめたのか」が曖昧になる。

- **待ち行列の読み取りと `flush()` は同じ同期ターンで行う。** 別々の `evaluate` に分けると、
  その間の計測ティックで行が増え、何件が書き込まれたのか合わなくなる。
- **基準の取り直しの検証も同じ同期ターンで行う。** 次のティックまで待つと、判定側が
  「スコアがしきい値を超えた」として `lowSince.wake` を消すため、`calibrate()` が
  リセットしたのかどうかを区別できない。
- **クールダウンは「一定時間出ないこと」では見ない。** 待ち始めた時点でクールダウンが
  どこまで進んでいるかに左右される。1 件目と 2 件目の間隔そのものを見る。
- **励ましカードは 1.7 秒ほどで自動的に消える。** 表示されている瞬間を狙って調べると
  取りこぼすので、`MutationObserver` で出た瞬間の見た目を控え、回数と間隔はイベント履歴で見る。
- **優先順位は 3 件目で見る。** 1 件目の時点では笑顔側がまだ継続時間に達しておらず、
  同着になっていないため、優先順位を入れ替えても結果が変わらない。
- **書き出す範囲は前の日の行を仕込んでから比べる。** すべて当日のデータだと、
  範囲指定を無効にしても結果が変わらない。

## 検証していない範囲

- 実カメラと実 MediaPipe による推定精度。スタブは blendshape の値を直接与えているため、
  **覚醒スコアが実際の眠気とどれだけ対応するかは、このテストでは何も言えません**。
- 覚醒スコアの重みとしきい値の妥当性。経験的に置いた値で、PVT や脳波との対応づけは行っていません。
- 同梱アセットで実際に解析が動くこと。10 節が確かめるのは「同梱があればそちらを選ぶ」ところまでで、
  MediaPipe 自体はスタブに差し替わっています。実物での確認は `npm run fetch-assets` のうえ手動で行ってください。
- IndexedDB を使えない環境（プライベートウィンドウなど）での挙動。
- Safari / Firefox での動作。
